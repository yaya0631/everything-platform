# Independent Adversarial Verification Report — "Everything" port to self-hosted

**Date:** 2026-10-25 · **Verifier:** independent agent (did not build this system)
**Target:** `D:\Stream\everything` — `platform/` (Node server, port 8080/8081) + `upstream/` (forked HeyPuter/everything @0fc4d361 base) + `platform/data` (runtime)
**Method:** black-box + white-box: real Chrome against the live server, API probes, netstat/egress capture, isolated-server robustness tests, static audits (3 subagents), functional test waves (subagents). Builder's docs/tests were read but never trusted; every claim below was re-derived. `CAD_TEST` was never set by the verifier.

---

## VERDICT: **FAIL**

(with major caveats: the infrastructure is genuinely good and honestly engineered in places, but the port does not meet the stated requirements)

**One-paragraph justification:** The port's apps all load and the platform is LAN-only at the browser level (zero external requests in 51/51 apps, offline-simulation identical) — but the single hardest requirement, *AI backed by self-hosted local models*, is simply not implemented: every AI call is proxied to **OpenRouter (cloud)** with the owner's API key, local Ollama is *disabled*, and every non-chat AI feature the original apps have (image generation, text-to-speech, OCR, transcription, AI video) is a **stub returning 501** with a fictional "install an engine" promise. Beyond AI: `puter.peer` (online multiplayer, meetings, huddles, live presence in 9 apps) and `puter.events` (realtime updates) are **missing entirely**; the **email app is dead on load**, **cap-table is dead AND poisons user data**, and a worker-runtime identity bug (ctx.user lacks .puter) makes the multi-user backends of **teamchat, legal, childcare, fleet, field-service, property-management and help-desk 401 every signed-in caller** — teamchat is wholly unusable; the "works 51/51 / AI parity in every app" status claims rest on an infrastructure probe that pings a **canned fake-AI echo**, not on feature tests. A normal user would notice within minutes: half the AI buttons error out, online games and meetings cannot start, and two apps are broken outright.

## 1. What this port actually is (verified architecture)

- Node 22+ server (`platform/server.js`), two listeners: private :8080 (everything), public :8081 (share links only, no cookies). SQLite (`platform/data/cad.db`), files on disk. Deps: `ws`, `nodemailer`, `puppeteer-core` (dev).
- All 51 upstream apps are built into `data/hub/apps/<app>` and served at `/h/<app>/` behind a **serve-time rewrite layer**: `js.puter.com` → local shim (`/hub/puter.js`), external script/link tags stripped, strict CSP (`default-src 'self'; connect-src 'self'`), service workers guarded from caching `/api`/`/wr`.
- The shim (`lib/shim/puter.js`) implements fs (grants + consent overlays), kv (11 methods), auth (partial — **no whoami**), workers (forked, network-blocked), ui pickers, **ai.chat only**; stubs txt2img/tts/stt/txt2vid/OCR; **no peer, no events, no usr/apps**.
- Hub home `/` = launcher listing apps under their **upstream package names** (accounting→"bookkeeping", email→"puter-mail", assets→"assetdesk" — verified against upstream package.json, not builder renames) with a local sign-in page.

## 8. "Differences I would notice" (plain language)

If you sat down at this server expecting the original apps, here is what you would hit:

1. **Every AI feature that isn't plain chat is missing.** Photo-studio "Generate image", audio-studio's TTS voices, video-studio's transcribe/voiceover/AI-video, contracts/expense OCR: all error out with "not available on this server — install the engine" (and documents goes further — its "Generate with AI…" menu item silently disappears). There is no engine to install; the buttons are dead ends. Documents' Read Aloud still works via the browser's built-in speech. You would notice within the first hour.
2. **Chat AI works but is secretly cloud.** Assistants answer well and fast — because every request is proxied to openrouter.ai with the owner's API key (proven by packet capture). Unplug the internet and every assistant in every app dies. The requirement was the opposite: local models.
3. **Online games and video meetings are gone.** Chess/checkers/backgammon "Online" and meetings "Start" show a raw JavaScript error ("Cannot read properties of undefined (reading 'serve')"). Local vs-computer play works fine.
4. **Two apps are broken outright.** Email shows an error card at boot ("puter.auth.whoami is not a function"). Cap Table shows "Couldn't read your saved data" on a brand-new account — and quietly poisons its storage so it stays broken.
5. **Realtime-ness is reduced.** Without puter.events, apps that live-updated (chat, mail arrival) fall back to whatever polling they have; some things only update on refresh.
6. **The home screen is different.** A custom "Hub" launcher with renamed apps ("bookkeeping", "puter-mail") instead of the Puter desktop, a local sign-in page, consent dialogs for drive access. Polished, but not the original.
7. **3D's Python scripting can't work offline** (Pyodide is fetched from jsdelivr), fleet's VIN/recall lookups need NHTSA, and publishing "public links" (contracts/invoices/hosting) is switched off until the owner enables hosting.
8. **The office suite mostly works** (verified end-to-end: spreadsheet formulas/autosave/reopen/.xlsx export, documents typing/autosave/.docx export, presentation slides/reopen, pdf annotate/export) — but pdf's "Save to Puter" fails on every re-save with a server error (a one-line bug), losing the annotation. PWA manifests 401 (can't "install" apps), occasional missing icons (meetings' icon-128), console noise, email-send buttons error until SMTP is configured (honest message).

What you would NOT notice (genuinely good): all 51 apps load fast and render pixel-faithfully with zero external traffic; create/edit/save/reload works in the CRUD apps tested (invoicing, POS, contacts, calendar, tasks…) and in the office suite (spreadsheet, documents, presentation); accounts, drive, sharing and multi-user isolation are solid; kill-the-server resilience is real (data survives hard kills); the CAD app — the builder's flagship — is excellent, including an AI assistant that actually edits the drawing.

## 9. What was NOT tested and why

- **True upstream AI quality baseline**: Puter's ai.chat requires a Puter account; anonymous calls hang. No account was available → the port's chat quality is evaluated on its own merits (deepseek-flash class via OpenRouter), not statistically against the original.
- **Pixel-diff vs real Puter rendering**: would require building all 50 upstream apps against real puter.com. The served bundles ARE upstream code (mod rewrite), so app-internal visuals are near-tautologically identical; the hub chrome (launcher/sign-in/consent) is where visual divergence lives and was captured.
- **Deep feature flows in**: records, expense, contracts (generic probe couldn't locate entry points; screenshots saved), pdf reopen-with-annotation (blocked by the M13 save failure), music-studio/parametric/circuits/building-design editing, 3d Python runtime, childcare/field-service/fleet/hiring/legal/property-management/shifts CRUD, wiki multi-user, signatures UI (their own e2e covers 27/27; my coverage = load+status), solitaire/sudoku deep play (load-verified only), CAD 2-user live collab at runtime (platform suite covers live-sync; my 2-browser script crashed on a harness bug).
- **WebRTC media quality on LAN**: moot — meetings cannot start at all (peer missing).
- **Long-run stability / memory over days**: out of audit window. Idle server RSS and boot time only.
- **Fresh-machine install from scratch**: first-run boot verified (fresh data dir boots, creates DB, serves CAD); full `npm run setup` + hub build of 51 apps NOT re-executed (needs network + ~long build); documented that a fresh install serves zero hub apps until the separate build step.

## 10. Prioritized fix list

Ordered by severity, then by how much each item hurts the "can't tell the difference from the original" goal. (Verifier does not fix anything; this is the repair order I recommend.)

1. **C1 — Make AI local.** Install Ollama (or another local inference server), pull models that cover the load (chat + tool-calling), enable the `ollama` provider, remove/disable the cloud keys, and set `hubAiDefaultModel` to a local model. Until this is done, the single biggest requirement of the port is unmet and every assistant dies offline. (Config + ops work; the platform already speaks Ollama.)
2. **M11 — Worker identity contract.** Provide `ctx.user.puter = { username, uuid, authToken: <local session token> }` (or patch the deployed workers' `identify()` at install time) so `user.puter`-checking workers stop 401-ing. This single fix revives teamchat, legal, childcare, fleet, field-service, property-management, help-desk multi-user backends. Smallest change with the largest app-count payoff.
3. **M13 — One-line fs bug.** `lib/hub-fsops.js:303`: `res` must be `let` (const reassignment throws on every dedupeName-on-existing save). Fixes pdf "Save to Puter" re-saves and any app with the same save semantics.
4. **M1 — Add `puter.auth.whoami`** to the shim (alias of getUser). Revives the email app's boot.
5. **M3 — Implement the AI engines** the README already promises (local Stable Diffusion/tesseract/Piper/whisper wiring + the Admin→Hub switch), or remove the buttons/claims honestly. Image generation and TTS are headline features of 4+ apps.
6. **M2 — kv.add array semantics.** Append array elements (match Puter's list_append behavior apps rely on) and clean the poisoned `captable:*` keys. Revives cap-table.
7. **M4/M5 — Implement `puter.peer` and `puter.events`** (LAN signaling on the existing WebSocket; local event bus). Restores online chess/checkers/backgammon, meetings, teamchat huddles, live presence, and realtime updates. Biggest engineering item; until then, replace the raw TypeErrors with the "named not-yet error" the README already promises.
8. **M12 — Whiteboard share path.** Serve `/worker/whiteboard-worker.js` under `/h/whiteboard/` (or rewrite the root-absolute fetch at serve time like other rules) so share/invites work.
9. **m6 (RETRACTED)** — the spreadsheet/presentation reopen concerns were probe artifacts; the completed f1 runs verified both round-trips end-to-end. No fix needed.
10. **M7 — Purge/lock the leftover admin tool accounts** (appsmoke has a repo-hardcoded password) and rotate the OpenRouter/Google keys (they sit in plaintext SQLite).
11. **M8 — Consent for `perms.request('folder')`** (show the same overlay as other drive grants).
12. **M6 — Vendor Pyodide** into the 3d app so Python scripting works offline; decide fleet/NHTSA policy (proxy-or-disable with an honest offline message).
13. **m1/m4/m5/m3 — Polish**: allow PWA manifests for authenticated sessions, add `frame-src` policy for embeds (or an owner-controlled allowlist), meetings calendar sidebar, Secure cookie flag when served over HTTPS.
14. **M10 — Make the status tool honest**: gate "works" on app-level feature probes with REAL AI (never `test:test-model`), and show email/cap-table/teamchat as broken until they are.

## Postscript — what the builder got right
For balance: the serve-time rewrite/CSP isolation is genuinely airtight (zero external requests in 51 apps, verified online AND offline); kv/fs/accounts/sharing/isolation/worker-sandboxing are solid and well-tested (649/649 suite green in my hands, and the suite is real); crash-resilience works; the CAD app — drawing, saving, AI-with-tools, live-session infrastructure — is the best-engineered piece and would pass as a commercial product's v1. The failures are concentrated exactly where the hardest work was promised and not finished: local AI, peer/events, and app-level parity for the apps whose backends depend on the missing contracts.
